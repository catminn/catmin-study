# Dungeon client projection boundary v1

Spoiler-free authoring/DM contract; this is NOT proof of an engine fix. The original dungeon schema already uses cast: [[displayName, publicRole, directorSecret, revealChapter], ...]. The fourth tuple item is a zero-based chapter index (as used by the original page/zhushen.html); no new reveal property is required. cast[i][2] is an author-only secret even after that character's name is revealed. The first two elements may be returned only after the server has authorized revealChapter. Never include unrevealed names. A compatible public tuple is [name, publicRole, null, revealChapter].

ALLOWLIST, NOT CLONE-AND-DELETE. Public GET /api/dungeons may expose the approved dungeon identity/description, intentionally public chapter titles, current authorized practice IDs/questions, and approved skill display metadata. Future chapters must not expose learning tasks, skill effects, or narrative body. The author fields pre, recap, zero, clear, hidden, ch[].s, ch[].sb, ch[].tn, and unselected fork.b must never be sent raw to the browser. These may contain director-only setup, alternate branches, or future facts. Authoring must provide separately approved public opening/summary text if the UI needs it. practice[].a stays server-only; practice[].hint is returned only after an incorrect server-checked attempt, not preloaded in GET. The current chapter's fork prompt can be made public only after its chapter/event gate; the alternate script remains private. Do not assume that reaching the final chapter makes director fields public.

Derive chapter and cast visibility from persisted server-side verification and authorized events, never client claims. Reject malformed cast tuples during authoring; if a bad record reaches a public endpoint, fail closed. Do not mutate the author record, mix dungeon/world progress, or allow a model to print private context without an authorized reveal event. Network responses, browser state and frontend bundles all count as disclosure surfaces.

The companion Node tests use synthetic sentinel content. By default they exercise a reference projection, NOT the current server. Set DUNGEON_PROJECTOR_MODULE to an importable module exposing projectDungeon(dungeon, verifiedSet) to run the same cases against an implementation. Claude owns real Worker/D1 tests and compatibility; the private first-world candidate must not be imported until actual server responses pass negative leakage tests.
