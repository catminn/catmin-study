# Deferred callback trace continuity — spoiler-free author reference v1

**Scope:** Offline synthetic author QA only, building on `cross-chapter-consequence-v1`. This is a deterministic trace *reference*, not a real Worker/D1 event processor, a trusted authorization mechanism, a production migration, an import format, or proof that an NPC remembers anything. All identifiers in the tests are invented `demo.*`-style placeholders. The first formal world remains **DO-NOT-IMPORT**.

## Why the static outline is insufficient

A chapter outline can guarantee that every possible route passes an *eligible callback slot*, yet a runtime may lose the earlier committed choice, display both mutually exclusive callbacks, replay a transition twice, or advance past a due callback without ever projecting it. This reference checks those **trace semantics** on a small synthetic two-chapter graph. It does not validate any real plot or real engine behavior.

`createDeferredCallbackTraceReference(outline)` first requires the existing static validator to pass, then copies its chapter/beat graph. `openSession()` creates an isolated, in-memory author test session. Its cursor starts at the first chapter's entry. `preview({to})` and `ask()` do not change state. `step({chapterId,fromNodeId,to,commitId,source:'server'})` follows only an actual outgoing edge, records the selected opaque impact on a branch, rejects stale chapter/scene provenance and conflicting commit IDs, and accepts exact replay idempotently. `advance({fromChapterId,toChapterId,commitId,source:'server'})` requires the current terminal beat and the immediately next chapter (or `null` after the final chapter). It rejects a trace that attempts to leave a due chapter without rendering a callback for every selected, due impact. This rejection is **a test failure**, not a proposed live story gate.

`render()` at the current beat counts only callbacks whose impact was selected in this session and whose deadline has not passed; it records their appearance for later QA. A callback for the competing unchosen route is never eligible. The interface returns fixed error codes, boolean statuses and aggregate counts, not opaque keys, scene IDs, prose or dialogue. The test runner checks two distinct route choices, missing projection, ASK/preview immutability, stale source, cross-session isolation, idempotent replay, conflicting event IDs, chapter order, and caller mutation of the original outline.

## Trust and gameplay boundaries

The literal `source:'server'` is **only a synthetic assertion** and is trivially forgeable in a real request. It must never be used as authentication or treated as a valid event signature. The actual engine must derive event provenance, session scope, cursor/revision pinning, choice ledger, and authorized conditional copy from trusted server state, with atomic persistence and multi-turn tests. In particular, real players must **not** be blocked by a missing narrator callback; such a condition should be detected in QA and corrected before release, not turned into a runtime softlock. ASK, preview, study visits, optional tutoring and practice scores must not synthesize route choices or advance the story frontier.
