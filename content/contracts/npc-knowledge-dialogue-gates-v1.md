# NPC knowledge-gated dialogue — author acceptance v1 (spoiler-free)

This contract extends the synthetic NPC testimony reference, not the live DM, the private first-world package, or any production API. All sample facts, characters, dialogue and route identifiers are invented placeholders. Claude owns authenticated persistence, content review enforcement and engine integration; the narrative author owns dialogue eligibility and experience acceptance.

An independently approved public copy may declare `requiresNpcKnowledge: { factId, tier }`. `factId` must be a known author-policy fact. `tier` must be exactly `heard` or `confirmed`, with no additional gate keys. A `heard` gate accepts an NPC's committed heard claim **or** confirmed knowledge; a `confirmed` gate requires that NPC's confirmed knowledge. A player's discoveries never satisfy an NPC knowledge gate. The gate is evaluated only after the existing same-scene, available-NPC, approved-copy and relationship checks. Missing, malformed or unsatisfied gates yield `{ available: true, text: null }`, not an alternative explanation.

An approved neutral line can be conditioned on private NPC knowledge without revealing that fact: the projection contains only `available` and reviewed `text`, never fact IDs, gate tiers, route traces, commit IDs or private state. A private knowledge gate is **not** permission to disclose the private fact in the line. The actual line must receive independent field-level human approval. No model-generated copy, model-declared memory or unreviewed text may become an approved line through this reference. An ASK or preview never creates knowledge or unlocks a line.

The synthetic policy adds three demonstration slots: heard-tier, confirmed-tier and a neutral private-knowledge-conditioned response. They are not proposed first-world dialogue. `test/npc-knowledge-copy-gates.test.mjs` contains eight Node.js tests for ignorance, hearsay versus confirmation, independent verification, player/NPC knowledge isolation, private-gate projection minimization, malformed gates, availability/relation/approval and ASK/preview immutability. Run `node --test test/npc-knowledge-copy-gates.test.mjs test/npc-event-id-safety.test.mjs` from the repository root. These tests exercise only the author reference; they do not validate live Worker/D1, real story content, real approvals or model narration.
