# NPC branch dialogue distinction — synthetic author QA (spoiler-free)

The existing NPC route bridge already requires distinct route traces, relation labels, approved public-copy records and different **raw** dialogue strings. That last check was insufficient: changing only case, spacing, Unicode compatibility forms, combining marks, or invisible formatting could make two visually equivalent responses pass as different route consequences.

The author-side bridge now compares a conservative canonical key for each already-approved public line: Unicode NFKC, removal of selected invisible format characters and variation selectors, whitespace folding and locale-independent lowercase. The helper is `scripts/npc-dialogue-comparison.mjs`; the bridge only uses it for the two synthetic sibling-route dialogue lines. When both normalize to the same key, the existing fixed `route_consequence_erased` diagnostic is returned. No text, ID, relation, trace or comparison key is emitted by the validator. This comparison is not a player-facing renderer or storage format.

The new tests use **invented dialogue only**. `test/npc-dialogue-comparison.test.mjs` checks the pure helper, and `test/npc-dialogue-comparison-bridge.test.mjs` checks that the route bridge rejects superficial differences while accepting genuinely different lexical text. The pre-existing route bridge tests remain the compatibility baseline.

This is intentionally conservative: distinct emoji presentations can be considered equivalent if they differ only in a joiner or variation selector. A false rejection asks the author to write clearer route-specific dialogue; it must never block a real player. Lexical distinction cannot establish meaningful narrative consequences, approved private story semantics, NPC memory, or correctness of a real model's response. It is not an import gate, an authorization check or evidence that any formal-world content was reviewed. First formal world stays **DO-NOT-IMPORT** pending private review, Worker/D1 tests and Catherine's explicit authorization.
