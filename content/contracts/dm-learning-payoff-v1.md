# DM learning payoff — synthetic cross-contract preflight v1

**Boundary:** Public, spoiler-free author-side contract. The fixture contains only invented demo identifiers. This is not a real-world content binding, author approval, server authorization, model evaluation or deployment instruction.

A DM can offer a concept and a chapter can teach it promptly, yet the supposed in-world application may point to a *different* skill or to no eligible world action. The existing DM beat, chapter alignment and skill→exit checks are necessary but independent. This additional bridge binds the actual DM `lesson_offer.applicationRef`, a committed DM route trace, the aligned chapter skill, its chapter index, and one registered optional skill-enhanced world exit. It also binds the existing ungated `baseActionKey` to preserve a nonacademic route.

The exact synthetic link fields are `schemaVersion: "dm-learning-payoff-v1"`, `synthetic:true`, `worldId`, `dmRevision`, `dungeonId`, `actionRevision`, `lessonBeatId`, `applicationRef`, `skillId`, `chapterIndex`, `actionKey`, `baseActionKey`, `routeBeatId`, `traceRef`, `worldFrom`, `worldTo`. The DM and skill-action revisions use distinct existing namespaces (string versus integer), so both are checked against their own source contracts, **not** treated as cryptographically equivalent. The link itself is an author assertion, not trusted provenance.

The validator first runs the existing DM beat flow, DM→chapter knowledge alignment, and four-skill world-exit validators. It then rejects cross-world/dungeon/revision mismatch, a lesson application reference not present in the actual DM offer, an unrelated route trace, an unrelated chapter skill, an action absent from the registered optional actions, or a different base exit. Diagnostics contain only fixed codes or counts.

Run `node --test test/dm-learning-payoff.test.mjs` with Node 22. This check cannot prove that a math concept truly helps solve the scene, that a player sees the optional advantage, that the model narrates it correctly, or that a server commits it.
