# DM optional learning payoff — combined author preflight v1

**Boundary:** Public, spoiler-free, synthetic-only author utility. It does not grant import approval, verify private story quality, run a real model, or authorize any runtime world action.

`validateDmPayoffFullPreflight({flow, chapter, alignment, actions, worldGraph, links, proof})` composes the three existing checks as one fail-closed entry point. It first validates consistency of the **two** distinct DM route links against the common route proof, then runs `validateDmLearningPayoff` separately on **each** route link, and finally checks the two-route world reachability proof. A single-route pass is never treated as sufficient. The source validators remain individually usable; this wrapper does not weaken their schemas or replace their validation logic.

Return shape is `{ok:true,validatedLinks:2,validatedRoutes:2}` or `{ok:false,code}`. Error codes are fixed stage-level labels (`input_invalid`, `cross_route_invalid`, `route_link_invalid`, `route_reachability_invalid`, `invalid_input`) and never contain input identifiers, text or underlying error messages. The root accepts exactly seven named fields; route links must be an array of exactly two. The wrapper is not wired to production, deployment, CI, or an import gate.

The orchestration unit tests use synthetic validator stubs through Node 22 synchronous module hooks to prove that both routes are checked, short-circuiting is safe, and diagnostics do not echo author content. Run with Node.js 22 using `node --test test/dm-payoff-full-preflight.test.mjs`. **These unit tests are not real-validator integration tests.** A separate `test/dm-payoff-full-preflight.integration.test.mjs` now exercises all three actual validators together against nine fully synthetic positive/negative cases (both routes, second-route binding, reachability, chapter learning, DM flow and fail-closed diagnostics). The integration cases passed 9/9 using exact GitHub source in an isolated V8 module adapter; native Node execution of the new integration file and complete repository CI have **not** yet been run. Neither test set proves server behavior or author approval.

Even when every check passes, route-to-world entry mapping remains author-declared; actual learning causality, ordinary exits, server authorization, model presentation and private field-by-field review are unverified. The first formal world stays **DO-NOT-IMPORT** until private review, engineering verification and Catherine's explicit in-person authorization. Never place actual plot, NPC identity, hidden facts, puzzle solutions or private identifiers in this public contract or tests.
