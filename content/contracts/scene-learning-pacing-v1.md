# Chapter learning pacing — spoiler-free author acceptance v1

This is a synthetic **author-side chapter-beat pacing preflight**, not a runtime turn counter, an academic grader, a private-story review, or an import gate. It uses the existing `validateSceneLearningFlow` contract first, including its unconditional story exits and optional practice opportunities. All example IDs are invented.

A learning-first chapter should introduce its **first** teachable knowledge point by the third authored story beat and offer its **first** optional, previously taught practice by the sixth beat on **every** unconditional story route. These are defaults (`teachBy:3`, `practiceBy:6`) and may be explicitly overridden for a chapter, but an override is not a silent pass. Beat counts include the entry beat; they are **not** equivalent to DM turns, actual UI interactions, seconds, or a learner's decision to accept the lesson. Refusal or skipping the exercise must still leave the ordinary story route available.

The validator `scripts/validate-scene-learning-pacing.mjs` computes the latest possible first-teaching and first-practice beat over the entire directed acyclic chapter graph, using a longest unserved-prefix calculation at joins. This prevents an early-learning route from concealing a branch that delays learning until the epilogue. Once a route has offered practice, later story beats do not count against the *first opportunity* budget. Distinct branch-specific practice cards remain allowed. The underlying graph validator independently ensures each offered card has been taught in a preceding beat on every route that reaches it.

Run `node --test test/scene-learning-pacing.test.mjs` with Node 22. Fixed, no-echo diagnostics: `limits_invalid`, `graph_invalid`, `learning_not_reached`, `teaching_too_late`, `practice_too_late`. A passing result contains only the latest first-teaching and first-practice beat numbers; it never contains source IDs or narrative text.

This checks **structural opportunity**, not that the actual DM speaks naturally, the UI surfaces the lesson, the student can solve the practice, or the practice changes an in-world option.
