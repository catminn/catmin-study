# MATH 1920：首个学习型 DM 端到端纯机制切片

**Owner**: ChatGPT（行为规格、验收语义）；Claude（技术实现、数值配置、测试部署和 UI/UX）。
**状态**: 提议交接规范，不是已完成的功能或正式剧情。与 `rules-spec-v1.md`、`rules-spec-v2.md` 配合阅读。

## 目标和边界

只测试一个抽象的行动场景 `sandbox_math`，其资源、规则、时间与结果均为占位标识，不创作正式故事或角色。必须演示：开放输入 → 识别意图 → 自然教学 → 实际知识应用 → 预提交规则检查 → 游戏检定 → 确认结果 → 恢复上下文。支持随时一键跳至纯 MATH 1920 刷题。

* 知识主题：偏导数与梯度（可在未来替换），例如 (f(x,y)=x^2y+3y^2)，(
abla f(1,2)=(4,13))。
* 独立正确的非标准方法必须认可，例如 (g(t)=(t+1)^2) 的导数可以先展开，也可以用链式法则；两种方法结果一致。
* 本切片绝不根据故事化程度决定学术成绩；测试世界没有隐藏剧情。
* 所有数值、DC、提示次数、奖励系数均使用 Claude 管理的配置，不在 DM 提示词里写死。

## 每轮输入输出契约

输入包含 `inputText`、当前会话状态、已公开场景、已确认掌握证据、合法可用的世界行为，以及用户当前学习目标。

响应应有：
- `intentSegments`：ASK、LEARN、PRACTICE、EXPLORE、ACT 可组合；
- `academicEvaluation`：针对相关结论的正确性、推理有效性、提示依赖、验证状态；无实际解答则为 null；
- `proposal`：仅在玩家要求真实执行时提出动作；
- `gameCommit`：由服务器生成的唯一 actionId 与确定性判定记录；没有实际行动则为 null；
- `learningSessionDelta`：学习会话创建、暂停、恢复或进度更新；
- `narration`：以玩家意图决定篇幅，仅可叙述已经核实/提交的事实；
- `visibleFeedback`：必要学术错误反馈、轻量成就提示、非剧透可用检定信息。

在 `ASK`、`LEARN`、`PRACTICE` 场景，`gameCommit === null`；在 `ACT` 场景，只有通过既有规则验证的合法行为才能提交。前置资料或模型不可用时返回明确的不确定性，不编造答案或世界后果。

## 八项端到端案例

| # | 玩家输入/条件 | 预期处理 | 禁止后果 |
|---|---|---|---|
| 1 | “梯度和偏导的区别是什么？” | ASK。解释梯度是偏导数组成的向量，可展开提问；世界事件数 0 | 自动掷骰、推进时间 |
| 2 | “把偏导这一章系统讲一下。” | LEARN。建立带进度的学习会话，分知识块讲解、自然检查理解 | 要求先完成游戏行动、改变世界 |
| 3 | “你提示我一下怎么求 (f(x,y)=x^2y^3) 的 x 偏导。” | 引导后学生答 (2xy^3) 时记录 `assistance=major_hint`（视实际提示程度而定）；当前正确可用，长期熟练不直接升级 | 提示后正确自动认定精通 |
| 4 | “(
abla(x^2+y^2)(1,2)=(2,4))，因为所有数字都乘 2。” | 答案正确，但理由无效；指出一般情况不成立，记录混合证据，询问是否愿意解释自己的推导 | 直接判完美掌握或因错误理由否定正确数值 |
| 5 | “(g(t)=(t+1)^2)，我先展开得 (t^2+2t+1)，导数就是 (2t+2)。” | 独立确认正确替代方法，记录合理知识应用 | 只接受参考答案中的链式法则 |
| 6 | “我觉得可以先算梯度，先不要执行。” | MIXED 作为 Draft + ASK/LEARN，不提交游戏动作 | 把计划当成执行 |
| 7 | “现在就用刚才验证过的梯度方法执行。” | ACT。引用已确认推理，冻结可见合法条件，提交唯一行动 ID；按配置骰/确定性规则结算；叙述已经提交的结果 | 同一推理重复叠加知识优势；重试重复消费 |
| 8 | “先去刷 5 题，不要剧情。做完接着刚才的。” | PRACTICE，暂停故事，刷题并批改；之后显式或自然“继续”时恢复准确挂起点 | 把题目视为世界行动；强插剧情或丢进度 |

### 额外故障与恢复场景

1. **断线重试**：服务器已接受 actionId，前端断连；重试同 ID 返回原 outcome，掷骰不重做。
2. **学术正确、骰子失败**：证据记录仍然存在；正常执行预设游戏后果；现实积分只按真实学习规则结算。
3. **评分待验证**：暂缓知识加成及依赖正确性的奖励；已发生的真实专注不抹去；向用户解释无法确认并保留进度。
4. **非自愿中断**：教学第 3 段关闭网页，再打开应恢复第 3 段，同时世界事件序号不变。
5. **知识已经熟练**：玩家可直接调用既有稳定知识基础修正，不需要每次重答同一道题。
6. **提示和学术主动性**：请求解释本身没有惩罚；长期熟练由独立表现决定，不依赖自述。
7. **课堂资料和学术准确**：题目条件与课程材料冲突时，明确指出冲突，优先核对来源；不让故事规则改变现实微积分。
8. **自动学习导演**：如果用户说“今天只想冒险”，不再强制出题；但用户自行提出有效数学推理仍可计证据。

## 叙事与教学风格约束

- DM 对“我不会”回应应像自然对话，先给直观解释或一条有帮助的提示，不以大量任务菜单打断。
- 用户想听一章时讲够内容、明确知识范围；只想确认公式时就短答；要求刷题就停止叙事装饰。
- 提示应减少机械感；同一问题如果用户已连续两次表达不理解，换解释角度而不是重复原话。
- DM 不可为了预定教学目标故意制造失败、阻止其他成立的解决方案或泄露不可见规则。
- 零与 DM 协作：导师只看到必要的公开情境、课程资料与学习状态；不读服务器隐藏事实。
- 不把每次教学输出强制变成测验，但对独立掌握的判定必须有可靠证据。
