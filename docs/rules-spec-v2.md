## 1. 主神空间基地：实用功能与资源流

### 1.1 用户能做什么

基地首先是一个带世界感的学习工作台，不是装修游戏。功能模块可以自然整合现有页面而不重复造数据：

| 功能 | 操作/产出 | 状态来源 |
|---|---|---|
| 主控制台 | 查看当前世界和挂起的学习会话、继续任务 | Session + World Snapshot |
| 零 | 当前科目问答、分块教学、整理错题 | Learning Sessions / Knowledge Evidence |
| 学科档案 | 各科章节覆盖、目前熟练度、弱点、复习 | 已有学科主线 + Mastery |
| 任务/日历 | 现实作业、考试、日历及 Canvas 事件 | 已有任务与同步数据，记录来源 |
| 专注 | 10/20/30 分钟和学习记录 | Focus Sessions |
| 物资/建造 | 查看已开放的功能性设施、开始合法升级 | Base Assets Ledger |
| 收藏陈列 | 浏览已发现或已取得的探索收藏；玩家选择展示 | Discovery / Possession / Display 三状态 |
| 商店 | 现实积分兑换原有真实奖励，不购买剧情结局 | Legacy Reward Ledger + Event Rewards |
| 世界记录 | 查看已公开历史与可合法恢复的世界 | Player-Known Events + Switch Policy |

### 1.2 不同资源绝不混账

- **现实积分 RealPoints**：来自符合既有奖励规则的真实学习/现实任务，兑换游戏时长、外卖、自定义奖励。延续旧存档价格与余额。
- **基地建设资源 BaseMaterials**：真实学习的长期累积成果可触发获得、解锁设施/升级；数量与产出率由 Claude 平衡。可升级的是学习功能和基地便捷性，而非必然成功率。
- **游戏内物品 WorldItems**：世界探索、规则允许的游戏行动获得和消耗；必须带来源世界及权限，不可自动兑换成现实积分。
- **收藏 Discoveries**：分别记录 discovered、owned、displayed，发现不等于拥有，拥有不等于展示；稀有收藏主要来自探索，不用现实积分直接购买。
- **知识能力 Mastery**：真实能力与证据，不是一种可消耗货币；基础加成和现场应用根据证据，不允许买等级。

资源流：`LearningEvidence(confirmed) -> RewardPolicy -> RealPoints / BaseMaterials`（两条合法用途，防重复领）；`WorldEvent(confirmed) -> WorldItems / Discoveries`；`BaseMaterials + UpgradeRule -> BaseFacilityLevel`；`BaseFacilityLevel -> 更好查看知识地图/恢复进度/整理资料/学习便利`。**基地不会修改学术真假，也不会自动替玩家做游戏决定。**

### 1.3 功能型基地的边界案例

- 用户完成真实作业：可以得到按旧规则核实的真实积分，并在建设规则允许时产生基地建设资源；一条来源事件只对每个奖励策略结算一次，不因重复点击结算多次。
- 用户阅读纯剧情：不自动发真实积分/基地建设资源。若现场有独立学术应用，学习证据另行确认。
- 收藏品只被“发现”：图鉴可显示已发现条目，但背包里不应出现物品。
- 消耗世界物品：绝不能扣现实积分，除非用户在真实奖励商店执行了另一项独立且明确的兑换。

## 2. 并行世界的 switchPolicy：三种纯机制示例

以下 ID、条件及效果均为占位机制，不包含任何实际世界内容。

**示例 A：随时可挂起的世界**
```json
{"mode":"free","preconditions":[],"onSuspend":[{"op":"checkpoint"}],"onResume":[{"op":"restore_snapshot"}],"worldTimeOnPause":"frozen"}
```
用户可以在 UI 切换；角色的世界时间暂停，不触发无根据的事件。

**示例 B：仅达到安全检查点后允许游戏内离开**
```json
{"mode":"checkpoint","preconditions":[{"fact":"world.safe_checkpoint_reached","eq":true}],"onDenied":"explain_visible_constraint","worldTimeOnPause":"frozen"}
```
在游戏条件未达成时，世界内切换拒绝；但用户仍随时可暂停网页、找零学习、离线离开，不会被迫持续游玩。玩家只获允许公开的限制解释。

**示例 C：切换有已确定代价**
```json
{"mode":"conditional_cost","preconditions":[{"resource":"world.switch_charge","gte":1}],"onSuspend":[{"op":"consume","resource":"world.switch_charge","amount":1}],"atomic":true,"onDenied":"show_visible_cost_and_requirement"}
```
切换需明确执行，原子扣费；网络重试不重复扣。页面切换与“角色正式离开当前世界”必须分成不同接口，避免误操作。

### 2.1 跨世界关联数据

```json
{"linkId":"link-opaque","sourceWorldId":"wA","sourceEventId":"evtA","targetWorldId":"wB","effectRuleId":"effect-id","visibility":"hidden_until_discovered","status":"pending","idempotencyKey":"unique-key"}
```

允许的变化由**事先写好的关联规则**决定；双方世界存档独立，不得让 DM 在目标世界临时编造跨界惩罚。切换中断、重复提交、条件不符都必须可回滚或幂等恢复。游戏资产跨界时明确归属和转移权限，防同一件物品在两处被消费。

## 3. 自然引导学习：DM 可执行输入输出范例

所有输入均是抽象对话，不出现真实剧情或世界秘密。输出是回复方式范例而非必须逐字复述的台词。

| 玩家输入 | 推荐 DM 行为 | 禁止行为 |
|---|---|---|
| “我还不会这个公式，怎么办？” | 简短说明此处涉及的知识，先解释直观意义；给少量启发和继续学习的选择，保持世界暂停 | 不会就立即判游戏失败；强制十题 |
| “你先别说答案，我自己想想。” | 留出空间；只在玩家主动求助或存在事前明确风险提示义务时介入 | 直接泄露最优解或隐藏条件 |
| “我觉得可以用偏导来处理，但不太会算。” | 验证方法是否适用；按需教一小步偏导，保留原计划为 Draft，不自动执行 | 因出现正确术语就直接发优势或提交行动 |
| “这个方法是我独立推导的，你检查一下。” | 检查推导和适用条件，指出需要确认的步骤；若正确记录学习证据；等待明确 ACT | 把答案正确视为动作自动成功 |
| “先把这一章系统讲完。” | 进入 LEARN，会话存档；分知识块推进，按反馈调节难度，章节覆盖与熟练分开记录 | 为了沉浸而拖长叙事、强行带回世界 |
| “我明天考试，直接刷题，不要故事。” | 一键强介入 PRACTICE；直接出课程相关题、批改和反馈，暂停世界 | 强制旁白或每题加入剧情 |
| “我学会了，现在执行刚才的方案。” | 复核当前已确认推理、锁定判定条件，若明确且合法则 Commit，必要时程序掷骰 | 让骰子决定公式正误或补写未经验证的事实 |
| “刚才那个再讲一遍，我走神了。” | 回到准确 resumeCursor，换一种解释方式；不惩罚提问，不自动降熟练 | 重置整章、扣积分或改变世界时间 |

核心：**自然引导 = 有意义的情境动机 + 随需教学 + 玩家保持选择权**。可给“提示/直接讲/我再想想”等轻量选项，但不要每条消息让玩家填问卷。

## 4. 被用户拒绝或纠正的方案（不要再重提）

| 旧想法 | 用户为何不接受/纠正 | 当前规则 |
|---|---|---|
| 现实刷任务获得玩 RPG 资格，两者相互独立 | 用户明确：网站主要是“在冒险中真正学习” | 真正的知识获取发生在冒险内；现实任务奖励是辅助 |
| 大量基地视觉装修和动画 | 用户说主要自己使用，偏文字与实用 | 文字优先、基地功能性经营 |
| 固定教学/剧情比例或每轮选模式 | 用户选择“取决于我的需求”“根据当前意图动态控制” | DM 自动识别 ASK/LEARN/PRACTICE 等 |
| 遇到知识缺口强行插课、必须出题 | 用户选择“自然引导学习” | 只在适合时解释、提示、提供自主替代 |
| 始终完全公开判定，或始终完全黑箱 | 用户选择“混合透明判定” | 关键风险解释与非剧透复核，保留隐藏事实 |
| 纯骰子决定学习能力，或知识学会则游戏必定成功 | 用户选择“混合系统” | 学术真假与行动随机性独立，知识影响概率/可行性 |
| 每个世界必须完全独立或处处强制关联 | 用户选择“选择性世界关联” | 默认独立，有限预设可验证关联 |
| 由 ChatGPT 主管技术与部署 | 用户随后确认以 Claude 分工为准 | Claude 主导工程、数字平衡和 UIUX；ChatGPT 负责玩法/剧情 |

上述列为**用户已纠正的设计方向**，并非每一项都经历独立投票；勿夸大为正式逐条否决。

## 6. 与 v1 的接口交接和验收增补

- `BaseResourceEvent`：{id,sourceLearningEventId,policyId,amount,createdAt}，同一 (sourceLearningEventId,policyId) 唯一；实际倍率由 Claude 负责。
- `BaseUpgradeEvent`：{id,facilityId,fromLevel,toLevel,cost,sourceResourceVersion}，服务端验证条件并一次提交，失败不扣费。
- `WorldSwitchCommand`：{id,fromWorldId,toWorldId,actionType,expectedWorldVersion}。actionType 区分 `pause_ui`、`resume_ui`、`commit_world_switch`，只有最后一项进入 switchPolicy。
- `LearningGuidanceEvent`：{id,learningSessionId,trigger,teachingDepth,promptLevel}，是教学日志而不是世界事件。
- 测试：重复基地升级只扣一次；没有学习证据不产基地资源；收藏发现不等于获得；失败的切换不耗资源；UI 暂停在任何时刻可行；同世界约束不得泄漏秘密；上述 8 类输入 DM 响应保持自主选择和不剧透；快速刷题零剧情；长章教学恢复后原世界状态不变。

## 7. 技术与规则职责边界

Claude 负责配置：具体积分产出、各类上限、复习阈值、专注防作弊、模型成本和并发事务；ChatGPT 负责规则意义、玩家体验与自然语言风格、故事设计。当前世界内容包隐秘交付问题按 Claude 的意见**延后到纯机制切片通过之后**再设计，不通过公开 PR 或共享记忆传递秘密。
